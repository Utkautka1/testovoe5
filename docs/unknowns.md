# Документ выявления неизвестных (Fable-style Unknowns Discovery)

## 1. Контекст и цели проекта
Разработка сервиса генерации и редактирования векторных композиций из готовой библиотеки компонентов Figma для компании, оценивающей качество архитектурных и продуктовых решений Senior-уровня.

---

## 2. Анализ слепых зон (Blindspot Pass) и принятые решения

| Слепая зона / Неизвестное | Риск | Принятое решение |
| :--- | :--- | :--- |
| **Качество векторных SVG из Figma** | Figma при экспорте фреймов может включать фон секций или растрировать эффекты. | Экспортировать изолированные векторные поддеревья через `download_assets` (`svgAssets`) без background rects, сохранять чистую разметку с ID слоёв. |
| **Масштабирование и замена S <-> L** | При смене детализации пользователь теряет позицию и трансформации объектов на холсте. | Сохранять единую систему нормализованных координат и якорей: при смене размера детализации заменять SVG-модель с сохранением центра, угла и масштаба. |
| **Перекраска векторных слоёв** | Простая замена всех `fill`/`stroke` ломает светотень и контраст иллюстраций. | Разбить палитру на роли: `background`, `accent_primary`, `accent_secondary`, `neutral_dark`, `neutral_light`. Перекрашивать по семантическим классам/яркостным корзинам. |
| **Галлюцинации LLM при подборе объектов** | LLM может предложить объекты, которых нет в библиотеке 20 иллюстраций (нарушение ключевого ограничения). | Передавать в системный промпт DeepSeek строгий JSON-каталог доступных ID и тегов. Дополнительно валидировать ответ схемы через Pydantic. |
| **Поддержка Fabric.js для SVG** | Импорт сложных SVG в Fabric.js может объединять пути в нередактируемый единый PathGroup. | Загружать SVG через `fabric.loadSVGFromString`, группировать с сохранением структуры слоёв и возможностью экспорта чистого SVG. |

## 3. Требования к кодовой базе
* **Single Responsibility & длина функций:** каждая функция строго $\le 25$ строк, решает ровно одну атомарную задачу.
* **Безопасность конфигурации:** строгий запрет на хранение ключей в коде; валидация `.env` через `pydantic-settings`.
* **Документирование:** формат docstring с ответом на вопросы «зачем существует», «почему так реализовано», «что возвращает».
* **Логирование:** семантические логгеры (`core.logger`), отображение жизненного цикла операций.
